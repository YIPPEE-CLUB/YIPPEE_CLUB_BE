아래 8개 파일을 해당 폴더에 준비해야 합니다.

| 활동지 | PDF | 표지 |


## 관리자 계정과 카테고리

관리자 비밀번호를 대신 설정하거나 기록하지 않습니다. 사용자가 아래 명령을 직접 실행하고 이메일/비밀번호를 대화형으로 입력합니다. 계정 준비 전에도 카테고리 및 표시 변경 작업은 독립적으로 진행합니다.

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

개발 서버가 실행 중이 아니면 다음 명령으로 시작하고 `http://127.0.0.1:8000/admin/`에서 로그인합니다.

```powershell
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

기존 v1.5 명세는 공통 Category 재사용을 확정했지만 전체 카테고리 명칭은 미확정입니다. 현 Category는 자동 정수 ID와 name을 가지므로 요청된 `신체운동·건강`, `자연탐구` 두 항목을 추가하는 것은 확정된 공통 체계와 충돌하지 않습니다. 전체 분류 체계 확정을 의미하지는 않습니다. 아이 관심사와 활동지가 같은 Category 행을 사용합니다.

준비 도구는 이름을 먼저 확인하고 기존 항목을 재사용합니다. Category.name에 DB UNIQUE가 없으므로 작업 간 MySQL named lock과 트랜잭션을 사용합니다. 이미 동일 이름이 중복되어 있거나 DB collation상 동일하게 비교되는 다른 이름이 있으면 추가하지 않고 중단합니다. 자동 ID를 사용하며 기존 Category 모델/테이블/식별자 규격은 변경하지 않습니다.

```powershell
# 필요한 경우에만: 카테고리 두 이름 준비. 활동지나 파일은 등록하지 않습니다.
.\.venv\Scripts\python.exe scripts/prepare_sample_activities.py --prepare-categories
```

## 등록할 메타데이터

모두 **권장 연령: 만 5세 (60~65개월)**, 최소 개월 수 60, 최대 개월 수 65, 가격 0원이며 카테고리 두 개를 모두 연결합니다.

| 제목 | 난이도 | 최소/최대 소요 시간(분) |
|---|---|---|
| 단비와 보리의 징검다리 모험 | 하(easy) | 5 / 5 |
| 단비와 보리의 숫자 놀이 | 상(hard) | 10 / 10 |
| 단비랑 보리의 콩 놀이 | 상(hard) | 5 / 5 |
| 단비와 보리의 공 놀이 | 상(hard) | 15 / 15 |

설명은 각각 다음과 같습니다.

1. 인형을 집까지 안전하게 이동시키며 차례를 번갈아 가며 놀이하는 활동
2. 종이 길을 따라 숫자 카드를 활용하며 결승점에 도착하는 놀이
3. 숫자 카드에 맞춰 콩을 떠서 컵에 모으며 수 개념과 소근육 조절 능력을 기르는 활동
4. 가까운 거리와 먼 거리에서 공을 바구니에 던지며 신체 조절과 의사소통 능력을 기르는 활동

자료가 준비되면 관리자에서 같은 제목이 이미 존재하는지 먼저 검색하고, 있으면 덮어쓰거나 새로 중복 생성하지 말고 확인합니다. 각 자료를 **비공개**로 저장하고 네 자료의 DB 메타데이터·카테고리·저장 파일을 확인합니다. 일반 사용자 상세/파일이 404인지도 확인한 뒤 공개로 전환합니다. 실제 등록 자료의 제목/설명/파일을 기능 테스트 목적으로 변경하지 않습니다.

현재는 파일이 없으므로 자동 등록/공개 명령은 추가하지 않았습니다. 부분 저장 후 실패했다면 관리자 목록과 저장 파일 참조를 먼저 확인하고 단순 재업로드하지 마세요. 기존 저장소는 파일을 자동 삭제하지 않으며, 트랜잭션과 파일 저장은 독립적입니다. 다음 일괄 등록 작업을 추가할 경우 사전 전체 파일 검증, 중복 확인, 시도별 파일 기록, 실패 시 이번 시도 파일만 정리하는 복구 절차가 필요합니다. 기존 미참조 파일 12개는 정리 대상에 자동 포함하지 않습니다.

## 검증 범위

`activities/test_sample_registration.py`의 합성 테스트 자료는 새 임시 저장소와 격리 MySQL 테스트 DB에서만 사용합니다. 누락된 실제 놀이북 파일을 대신 등록한 것이 아닙니다.

- 테스트 중에만 생성한 무작위 비밀번호로 관리자 로그인 확인. 실제 개발 관리자 비밀번호는 생성하지 않습니다.
- 카테고리 2개 준비의 반복 실행 시 같은 ID 재사용, 중복 이름 발견 시 미변경 확인.
- 추가/수정 화면 및 자료가 있는 목록에서 표시 이름 확인.
- 최소 개월 수 > 최대 개월 수 검증 유지 및 새 migration 불필요 확인.
- 4개 비공개 등록 후 가격/개월 수/소요 시간/공통 카테고리/저장 파일 바이트 확인.
- 비공개 목록 count=0, 상세/PDF/표지 404 확인 후 테스트 자료만 공개 전환.
- 공개 목록 count=4, 각 상세/PDF/표지 200 및 업로드 바이트 일치 확인.
- 검색·카테고리·연령·난이도 필터 및 잘못된 ID 404 확인.
- 기존 활동지 테스트의 수정·PDF/표지 교체·가격 변조 차단 및 기존 인증/아이 API 회귀 테스트도 함께 실행.

실제 개발 DB 검사는 읽기 전용 폼 렌더링과 목록/없는 ID 접근 및 저장소 설정 확인에 한정합니다. 실제 계정 로그인과 네 자료 등록 성공을 의미하지 않습니다.

## 최종 테스트와 보존 결과

- 격리 MySQL 전체 Django 테스트: **119개 중 117개 통과, 기존 preview 전용 2개 제외**. 신규 준비/4개 등록 흐름 테스트 5개와 기존 활동지/인증/아이 API 테스트를 포함합니다.
- 기존 스크립트 안전성 단위 테스트: **19개 통과**.
- Django system check: 통과. `makemigrations --check --dry-run`: 변경 없음. `migrate --plan`: 대기 작업 없음.
- 실제 개발 DB 카테고리 이름/자동 ID 및 관리자 폼 표시 확인: 통과.
- 가격 0원·개월 수·시간·난이도 CHECK 활성화 유지: 통과. 실제 DB에 제약 확인용 쓰기 테스트를 하지 않았습니다.
- 카테고리 생성 전에 새 읽기 전용 백업(26,838 bytes)을 생성했습니다. 기존 모든 테이블/행/FK/migration을 비교하여 카테고리 두 행 외에는 변하지 않았음을 확인했습니다. 이번 작업에서는 스키마 변경이나 migration 적용을 하지 않았습니다.
- 기존 `private_uploads/activities`의 파일 12개는 앞선 작업의 파일 목록과 SHA-256을 대조하여 동일함을 확인했습니다. 삭제/덮어쓰기/활동지 참조 생성 없이 그대로 보존했습니다. 임시 권한 검사 파일은 제거했습니다.
