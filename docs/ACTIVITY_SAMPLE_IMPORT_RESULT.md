# 실제 활동지 4개 등록 및 조회 검증 결과

프로젝트 루트의 `sample_activities/`로 이동한 PDF 4개·PNG 4개를 확인하고, 기존 개발 DB에 등록했습니다. 기존 migration 재적용이나 스키마 변경은 하지 않았습니다. 작업 브랜치는 `dev`이며 Git commit/push/PR/merge는 수행하지 않았습니다.

## 등록 결과

| ID | 제목 | 난이도 | 최소/최대 소요 시간 | 공개 |
|---|---|---|---|---|
| 1 | 단비와 보리의 징검다리 모험 | 하(easy) | 5 / 5분 | 예 |
| 2 | 단비와 보리의 숫자 놀이 | 상(hard) | 10 / 10분 | 예 |
| 3 | 단비랑 보리의 콩 놀이 | 상(hard) | 5 / 5분 | 예 |
| 4 | 단비와 보리의 공 놀이 | 상(hard) | 15 / 15분 | 예 |

모두 **권장 연령: 만 5세 (60~65개월)**, 최소 개월 수 60, 최대 개월 수 65, **가격 0원**입니다. 요청된 설명을 그대로 저장했습니다. 네 활동지 모두 기존 Category **1: 신체운동·건강**, **2: 자연탐구**를 연결하여 총 연결 행은 8개입니다. 기존 카테고리를 재사용했고 새 카테고리나 수동 ID를 만들지 않았습니다.

원본 파일은 수정하지 않고 Django Storage를 통해 `private_uploads/activities/{UUID}.pdf/.png`에 복사했습니다. 원본 파일과 DB 참조 파일, 실제 HTTP 다운로드 결과의 SHA-256을 각각 대조하여 PDF 4개·표지 4개 모두 일치함을 확인했습니다. 기존 20MiB/5MiB 및 형식 검증을 통과했습니다. 원본 폴더와 저장소는 Git 제외 상태입니다. `activities/sample_activities/`에는 폴더가 남아 있지 않았습니다.

## 등록·공개 순서와 보존

1. 실제 연결이 기존 개발 MySQL(`yippee_club_db`, 3306, 기존 서버 UUID)인지 확인하고 테이블 22개·migration 25개·활동지 0개를 확인했습니다.
2. 새 읽기 전용 백업 **26,934 bytes**를 생성하고 DB·원본 파일·기존 저장 파일이 바뀌지 않았는지 확인했습니다.
3. 네 활동지를 단일 DB 트랜잭션으로 **비공개** 등록했습니다. 파일 저장 전에 UUID 경로를 journal에 기록합니다. 일반적인 실패 시 DB를 롤백하고 이번 시도에서 저장한 미참조 파일만 정리합니다. 프로세스/DB 장애로 상태를 확인할 수 없으면 journal을 보존하고 자동 재시도를 하지 않습니다.
4. 비공개 메타데이터·카테고리·저장 파일 바이트를 확인했습니다. 실제 임시 로컬 HTTP 서버에서도 목록 count=0, 네 상세 404, 파일 8개 404를 확인했습니다.
5. 네 행을 잠근 상태에서 원본과 메타데이터를 다시 확인한 뒤 공개 전환했습니다.
6. 공개 조회 및 다운로드와 기존 데이터/파일 보존을 확인했습니다. 검증용 임시 HTTP 서버는 모두 정상 종료했습니다.

기존 테이블/컬럼/FK/migration 이력과 모든 기존 행을 비교하여 보존을 확인했습니다. 활동지 4행, 관계 8행, 파일 8개만 추가했습니다. 기존 미참조 파일 12개는 이름·크기·SHA-256이 유지되었으며 저장소에는 현재 총 20개 파일이 있습니다. 기존 사용자/아이/카테고리/인증 기록은 변경하지 않았습니다. migration 파일 12개의 이전 해시와도 일치하며 새 migration은 없습니다.

## 실제 API 검증

| 요청 | 결과 |
|---|---|
| GET `/api/v1/activities` | 200, count=4 |
| GET `/api/v1/activities/{1..4}` | 모두 200 |
| GET `/api/v1/activities/{1..4}/files/pdf` | 모두 200, 원본 PDF SHA-256 일치 |
| GET `/api/v1/activities/{1..4}/files/image` | 모두 200, 원본 PNG SHA-256 일치 |
| 없는 ID 상세 | 404 |
| 검색·카테고리·연령·난이도·시간·가격 필터 | 12개 조건 검증 통과 |

각 다운로드의 private/no-store 및 nosniff 헤더도 확인했습니다. 파일은 직접 공개 미디어 경로로 제공하지 않으며 기존 접근 제어를 유지했습니다. 공개 전에 동일한 ID와 파일 URL이 차단되는 것도 검증했습니다.

실제 HTTP 검증은 Django WSGI와 미들웨어를 사용하는 임시 loopback 서버에서 수행했습니다. 증거의 임시 포트는 종료되어 접속용 주소로 사용할 수 없습니다. 조회하려면 기존 개발 서버를 사용하거나 다음 명령으로 실행합니다.

```powershell
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

접속 예: `http://127.0.0.1:8000/api/v1/activities`, `http://127.0.0.1:8000/api/v1/activities/1`.

## 관리자 확인

개발 DB 사용자/활성 superuser는 여전히 **0개**입니다. 실제 관리자 로그인은 실행하지 않았고 비밀번호를 임의 설정하지 않았습니다. 관리자 추가 폼과 네 활동지 수정 폼은 저장하지 않은 관리자 권한 객체로 읽기 전용 렌더링하여 모두 200, 기존 개월 수 라벨 및 가격 읽기 전용을 확인했습니다. 실제 자료를 테스트 목적으로 수정하거나 파일 교체하지 않았습니다.

실제 로그인/추가/수정/파일 교체/공개 전환 검증은 격리 MySQL의 임시 계정과 임시 저장소에서 통과했습니다. 사용자가 실제 개발 계정을 준비하려면 다음 명령에 이메일과 비밀번호를 직접 입력합니다.

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

그 후 `/admin/activities/activity/`에서 4개 자료를 조회·관리할 수 있고 새 활동지도 직접 등록할 수 있습니다. ‘최소 개월 수’, ‘최대 개월 수’, ‘가격(원)’ 표시와 API 키는 유지되어 있습니다.

## 테스트와 복구 기록

- 이번 전체 격리 MySQL 테스트: **121개 중 119개 통과, 기존 preview 전용 2개 제외**.
- 실제 제공 파일을 사용한 4개 비공개 등록 → 공개 조회/바이트 일치, 동일 자료 중복 등록 거부, 저장 실패 시 DB 롤백·이번 파일만 삭제하는 테스트를 추가했습니다. 기존 인증·아이 API 회귀 검증을 포함합니다.
- 실제 개발 DB와 격리 환경의 system check 및 `makemigrations --check --dry-run`: 통과, 변경 없음.
- 테스트에서 발견한 Windows 경로 구분자에 따른 중복 정리 기록은 경로를 `/`로 통일하여 수정한 뒤 전체 테스트를 재실행했습니다.
- 실제 등록 후 첫 공개 검증은 검증 도구의 RequestFactory 기본 Host(`testserver`) 때문에 중단됐습니다. 네 자료를 비공개로 되돌린 뒤 도구에 localhost를 명시했습니다. 기존 네 행과 파일/백업 해시 및 다른 테이블 보존을 다시 확인하고 **재업로드 없이** 검증과 공개를 재개했습니다. 최종 실제 HTTP 검증은 모두 통과했습니다.

전체 테스트 증거는 `.mysql-rehearsal/child-tests-8be7b4b05064/`에 있습니다. 민감한 백업과 자격정보는 접근이 제한된 Git 제외 디렉터리에 있으며 내용이나 비밀번호를 출력하지 않았습니다.

## 추가한 도구와 남은 작업

`activities/sample_import.py`는 사전 전체 파일 검증, 중복 차단, 비공개 트랜잭션 등록 및 실패 정리를 담당합니다. `scripts/register_sample_activities.py`는 개발 DB 식별·백업·등록·접근 검증·공개·보존 확인을 수행합니다. 기존 활동지가 있으면 기본 실행을 거부합니다. `--resume`는 중단된 시도의 정확한 비공개 네 행/원본/백업/기존 데이터가 모두 일치하는 경우에만 업로드 없이 검증을 재개합니다. 이미 공개 등록이 완료되었으므로 다시 실행할 필요가 없습니다.

남은 작업은 사용자 직접 관리자 계정 생성과 실제 브라우저 로그인 확인입니다. 결제, 프론트엔드 전체 구현, 운영 영구 파일 저장소 구성은 이번 범위에 포함하지 않았습니다.
